# 实际动效样片：已观察的窄范围例子

检查日期：2026-10-01。对象为本次制作的15.3秒、1080×1920、30fps动效样片。它把原片39.6–48.4秒和74.4–80.9秒两段连接起来，用于检验机制；不是连续原片片段，也不能替代全片验收。

## 画面状态与解释作用

| 样片时间 | 检查到的变化 | 可迁移机制 |
| --- | --- | --- |
| 0.8→1.8秒 | 左侧模块由淡到实，关系箭头开始出现 | 先建立对象，再建立连接，保持同页上下文 |
| 1.8→5.2秒 | 平台模块、向下路径以及用户元素逐步形成 | 按讲述顺序展开因果/策略，避免开头展示完整答案 |
| 5.2→7.8秒 | 用户元素达到完整终态，结果文字落定 | 动作完成后留出阅读时间 |
| 8.95→12.7秒 | 真实协作界面局部推近，出现关注区域框 | 保留真实证据，镜头和标注只负责引导注意 |

这些是编码结果中的实际状态变化，制作采用逐帧图层合成后编码。不是给同一张静图添加“动画说明”。样片中其他时间点的代码安全界面也有局部推近与框选；本次六阶段联系图主要验证上表机制。

## 检查的范围

- 已核对样片时长、尺寸、帧率和音视频流
- 已检查实际视频导出的六阶段画面，确认节点/箭头/用户构建以及UI焦点变化
- 区域差分排除了人物、字幕和进度条；例如平台/箭头区域变化像素约46.05%、协作UI区域约40.11%，静态标题区域平均差分约0.091。这些值只辅助证明对应区域不是静止，不能作视觉质量分数、阈值或全片动画覆盖指标
- 本例不声称已完成全片正常速度观看、完整声音验收或手机四平台发布遮挡实测。项目仍需按 `semantic-motion.md` 做连贯播放、语义时序与可读性检查

## 不要把例子当成固定插件

本skill只封装方法、分镜约定、数据检查与验收；没有内置上述项目的渲染引擎、媒体、账户或剪映自动化。执行时需使用实际可用的渲染/编辑能力。复用结构和动效方法，重新测量新片时间码；不要把本例产品结论、源秒数和像素差数值带入别的选题。
