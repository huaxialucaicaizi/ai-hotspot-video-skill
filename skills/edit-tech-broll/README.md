# AI 观点口播 B-roll Skill

一套能在 Codex / Claude Code 使用、方便交接剪映的剪辑方法。

重点不是“每句话配一张图”，而是：听懂原观点 → 确认它是事实、官方说法还是作者判断 → 为画面分配证明/解释/对比等任务 → 按语义触发变化 → 回到作者。

## 它会做什么

- 从带时间码原声拆完整语义段，保留作者论点和语气
- 将真实 UI 录屏、官方资料、关系图、具体场景与人物回场组合起来
- 丰富讲解需要真实动效：节点和箭头随原声建立、元素逐步进入、真实证据局部聚焦、高亮与人物回场；同页停留不等于整页静止
- 沿用白/浅灰、蓝紫渐变、柔和立体关系模块的科技风
- 按观点自主选择：A-roll 全屏、B-roll 全屏＋A-roll 小圆窗、上 B-roll 下 A-roll
- 先静态分镜，再代表样片，最后全片；已授权的完整制作无需反复确认
- 用户要求时加细进度条和当前章节，全片固定顶部或底部安全锚点，按整片时间连续推进
- 产出真实素材、字幕、时间码编辑清单和已实际制作的成片

## 它不是自动安装的剪映插件

Skill 提供决策方法与交接规则。真正录屏、转写、作图、渲染和打开剪映，需要所在环境已有相应能力。

通用交付包含媒体、SRT 和 CSV/JSON 编辑说明，需要在剪映人工导入和摆放。JSON 不是剪映原生草稿；只有在明确记录的剪映版本实际开档、重开和导出成功后，才交付“已验证原生草稿”。

动态项目还应交付已渲染的B-roll运动片段、动效分镜和真实存在的源文件。写了动画说明不等于已经执行；不能把静图轮播加人物口播、字幕或进度条当作完整动效。样片需播放检查B-roll内部变化，再扩展到全片。

本次修订附有15.3秒项目样片的[实际状态检查记录](references/tested-motion-example.md)：节点/箭头逐步建立、用户元素进入以及真实界面推近与框选。检查记录只证明注明范围内的实现，不表示skill内置视频渲染引擎。

## 本次进度条建议

全片使用固定顶区：以1080×1920为基准，章节文字约 x=120/y=300、字号30–34；细线 x=120–900/y=350、厚6；B-roll内容从 y=410以下开始。其他9:16尺寸按比例缩放，切换全人物、圆窗或上下屏时位置不变。

这是一份编辑建议，不是四个平台通用的官方安全区。小红书、抖音、视频号、B站的标题、按钮与设备界面不同，发布前需用各自预览或手机截图校准；B站弹幕仍可能覆盖。具体值可在项目清单中调整。

## 最快开始

1. 解压，保留整个 `edit-tech-broll` 文件夹
2. Codex：放到项目 `.agents/skills/`；Claude Code：放到项目 `.claude/skills/`
3. 把原视频、现有字幕和已确认风格放入独立项目目录
4. 调用 `$edit-tech-broll`（Codex）或 `/edit-tech-broll`（Claude Code），告诉它当前做分镜、样片还是全片

完整个人/项目安装说明与已核对官方链接见 [INSTALL.md](INSTALL.md)。本次提供文件包，未替你改动远程仓库或本机技能目录。

若你单独打开这份README，其中相对链接指向ZIP解压后的同名文件。

## 可直接用的请求

> 用这个 skill 重剪我的观点口播。保留原声、可读的中英字幕和观点顺序，沿用浅色蓝紫风格。先检查原片并按语义划段，真实 UI 和官方素材必须匹配原句，自制图标明作者分析。根据观点自主选择 A-roll 全屏、B-roll 全屏＋人物小圆窗、上下分屏三种构图，增加细进度条和当前章节。我已确认方向并授权全片，按内部静态检查、短样检查再完成全片。请交付成片和剪映用通用素材包，不要把自定义 JSON 当作可导入草稿。
