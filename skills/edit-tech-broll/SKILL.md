# 观点口播的 B-roll 剪辑

目标：让观众更容易理解、相信并记住原有观点。先决定画面的作用，再决定素材和动效；丰富来自证据与表达方式的变化，不来自堆字、装饰或固定频率切镜。用户要求参考型丰富讲解或指出“像幻灯片、没动效”时，必须制作真正随原声展开的 B-roll 内部运动，不能仅靠静图轮播、口播人物和进度条充当动态效果。

## 接手与边界

1. 确认本次 A-roll、原声、现有字幕、目标平台、比例和交付阶段；实际检查文件时长、帧率、尺寸、音轨及画面。不要把曾交付的片段当作当前全片。只差不影响工作的选项时采用已确认项目设置。
2. 完整听读原声，再校正转写中的产品名、数字、否定词和转折。时间码来自真实音轨对齐；只有文本时可先设计语义分镜，但必须标为“未对齐”，不能生成伪精确时间轴或声称完成剪辑。
3. 重剪默认保留作者原声、论点顺序和含义。发现事实问题或论证缺口，列出原句、依据与建议，不自行替作者改成立场更强的断言。删句、换声、重写或重新排序需有当前任务授权。
4. 区分规划能力、媒体处理能力、目标编辑器能力。没有本地剪映、合法可取素材或可用转写服务时明确具体缺口，继续能做的工作。不要声称已安装、已操控、已验证未使用的软件。

## 语义分镜

阅读 [语义与视觉决策](references/semantic-editing.md)。每个完整意思填写：时间范围、口播原文、论点、论述角色、证据状态、画面目的、素材、画面变化触发词和读完所需时间。用 [分镜模板](templates/storyboard.csv) 保存。

- 论述角色：提出观点、给出证据、解释机制、比较反差、具体场景、转折、总结
- 画面目的：证明、解释、对比、代入、强调、缓冲。一个主要目的优先；“好看”不构成素材入选理由
- 把断言分成已核实事实、官方宣称、作者分析、待核实项。引用来源能证明什么，就只让它证明什么
- 以对象、论证关系或观点状态变化作为换镜触发。同一图上高亮/显露足够时不换图；不要每个名词、字幕行或固定两秒生成新画面
- 每段结束要能回答：“这个画面比只有口播多传递了什么？”没有答案就回到作者

## 把动态讲解落实为运动

需要丰富讲解时，必读 [语义动效](references/semantic-motion.md)，填写 [动效分镜](templates/motion-storyboard.csv)。同页停留是保留视觉上下文，不是把整页冻结到下一句。

- 关系图按原声次序建立节点、路径与结果；讲到的对象进入或高亮，讲完后保留可读终态，不在开场把所有答案同时铺满
- 真实界面/官方证据用有目的的局部镜头推进、跟随关注区或高亮；不靠整张截图持续漂移代替具体操作，更不能动画出不存在的产品功能
- 页内元素进入、重点切换与作者回场共同组织注意力。转场要看得清前后关系，不能只堆花式效果
- 每个运动记录起始/终止状态、原声触发词及时间、运动时长、缓动、关注对象和观众该理解什么；选择静止时记录阅读或判断上的理由
- 运动必须进入实际视频渲染。JSON里写了动画、导出了一组静态PNG或人物在动，都不算已经完成B-roll动效

## 画面选择顺序

| 内容需要 | 首选 | 必须避免 |
| --- | --- | --- |
| 产品真实功能、操作或结果 | 可核验的真实 UI 录屏；输入→关键动作→结果 | 假按钮、假结果、用别的功能 UI 充当证据 |
| 某次发布、某段官方表述 | 对应日期的官方公告、发布会/Keynote 原始画面 | 把宣传片误说成实测，拿其他发布会凑画面 |
| 原理、因果、流程、策略差异 | 自制关系图；按讲述依次显露关系 | 孤立关键词卡片、无依据的箭头或因果 |
| 用户任务、场景或抽象代价 | 与任务直接相关的实拍、授权素材或明确标注的情境示意 | 无关办公室/机器人库存画面伪装具体事实 |
| 作者判断、情绪、反问、转折和结论 | 作者回场或强化人物权重 | 用密集画面盖住关键判断 |

素材按 [素材证据与获取](references/asset-evidence.md) 记录来源、版本、使用权限和裁剪。生成图只承担示意或空间解释，不生成官方截图、品牌 Logo、发布会事实照片或产品能力证据。

## 默认视觉和构图

沿用白/浅灰底、浅蓝紫渐变、深色字、柔和阴影和必要的立体关系模块。具体规范见 [视觉与节奏](references/style-and-pacing.md)。这是可覆盖的项目默认值，不是声称测量过某博主的风格。该系列已允许按观点自主选择以下三种构图，无需把所有段落锁在上下分屏。

- 默认 9:16；作者判断、情绪、反问与结论用 A-roll 全屏；复杂图、证据界面或场景需要面积时用 B-roll 全屏＋A-roll 小圆窗；对照讲解、目录或简单说明用上 A-roll 下 B-roll。凡采用上下分屏，都按此顺序，除非用户本次明确指定其他构图
- 上方 A-roll 约 42%、下方 B-roll 约 58% 只是构图起点，实际人像、字幕与手机预览优先。口播字幕放在上方可读区域；原片烧录字幕若无法安全保留，应准确重建且不叠两套。小圆窗不要盖关键数字、关系节点或 UI 控件
- 三个目标平台底部的标题、文案和按钮会遮挡画面：在各平台发布预览中分别确认口播字幕不被盖住，同时将下方 B-roll 的关键文字、Logo、操作步骤与结果上移到实际可见处；不要把固定像素边距当成通用安全区
- 由语义需要选择和切换模式，不设置三种模式的硬配额；同一观点中不无故来回换构图。保留连续原声，不强行用 B-roll 铺满每秒
- 原片自带烧录字幕时，人物圆窗只裁人物会丢失文字；保留字幕区域或另行准确重建，不能声称字幕仍可见而实际被裁掉。重建不得改变原话，不额外叠两套重复字幕
- 项目明确指定固定构图时，以该次要求为准；新的其他模式需有明确表达收益、能保留作者和字幕，并纳入静态预览检查
- 正确品牌 Logo 从官方资源获取，保持形状比例。精确文字、图表、箭头用可编辑布局；视觉少而关系完整
- 用户要求进度条时：细线＋当前章节名，填充按全片实际已播放时间计算；全片固定在画布上沿或下沿的同一安全锚点，不跟随分屏边界或人物布局移动。平台按钮、标题和字幕覆盖范围需在目标应用实际预览；推荐边距不能冒称通用官方安全区。不要用整屏导航、百分比或花哨装饰抢注意；未请求时不擅自添加

用户提到小Lin说、黄白或其他创作者时，先按 [参考视频拆解](references/creator-analysis.md) 检查具体参考。只有名字时可采用“证据→解释→回场”的通用方法，但必须说明未进行逐帧风格比对。不要把未看的片子写成已拆解。

## 制作阶段

1. 先做静态分镜和关键起止状态：真实文案、真实 Logo、拟用素材、对照口播及出处；放入原 A-roll 手机比例合成检查。静态稿确认构图，不能代替动效验证
2. 风格和素材类型已确认后，用代表段落制作真正运动的短样片：能看到关系逐步建立或元素进入、证据焦点变化和语义衔接；通常 10–15 秒，不硬剪断一个完整意思。播放已编码样片，单独检查B-roll区域，再扩展全片；不能用开头/结尾两张图冒称已验收运动
3. 全片沿用已确认原则，按同一时间轴补齐素材并合成。用户明确授权全片时，静态/样片仍作为内部质量关，但无需重复索要已给的批准
4. 用户只要求分镜或样片时停在该阶段。新的重大视觉方向、缺失证据或会改动作者含义的问题才需重新决策

## 剪映与跨工具交付

必读 [剪映交接](references/jianying-handoff.md)。规划数据是编辑说明，不能冒称剪映草稿。

- **通用包**：实际媒体＋UTF-8 SRT＋时间码编辑清单＋来源记录＋预览/成片（如已产出）。这些文件需人工导入和摆放，不承诺一键导入时间线
- **可编辑原生草稿**：只有在记录的操作系统、剪映完整版本和适配器版本上，实际开档、重连、播放、导出并重新打开成功后才这样命名
- `templates/edit-manifest.json` 是本 skill 的中间格式，供检查和人工交接；绝非剪映/CapCut 原生格式。字段解释见 [数据约定](references/manifest-format.md)
- 使用 Python 3 标准库校验：`python3 scripts/validate_manifest.py PROJECT/edit-manifest.json --check-files --strict`。通过仅说明结构、路径和时间范围正常，不代表事实/画面/剪映兼容性通过

## 验收与交付

执行 [成片验收](references/quality-check.md)：时间轴和口型、手机可读性、事实素材对应、音频连续性、完整解码、首中尾及每次语义转场的人工抽查；记录没检查的范围。

先写临时输出，编码成功且检查通过后再移入交付目录。交付时明确“分镜／样片／全片／通用交接包／已验证原生草稿”、成片时长、未解决缺口及下一步。不要把安装说明说成已安装，把校验脚本说成剪辑引擎。

安装与调用见 [INSTALL.md](INSTALL.md)。该目录自包含，可在 Codex 和 Claude Code 中读取，不依赖任何特定平台的私有工具名称。
